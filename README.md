# gitlab-selfhosted

## Быстрая установка и запуск

    git clone git@github.com:luckacha/gitlab-selfhosted.git
    cd gitlab-selfhosted
    docker compose up -d

Первый запуск — 5–10 минут (инициализация БД).
Пароль root:

    docker exec gitlab cat /etc/gitlab/initial_root_password

Веб-интерфейс: http://localhost:8929, логин `root`.
Файл с паролем удаляется через 24 часа — смени пароль сразу.




# GitLab CE: разбор 

  GitLab в настоящее время недоступен для пользователей из РФ, опыт использования заканчивается на этапе регистрации и подтверждения личности.
Поэтому мной было принято решение использовать GitLab CE (Community Edition) вместо обычного GitLab. 

GitLab CE работает из одного Docker контейнера, в котором сосредоточено 7 процессов. Ниже расписана полная установка GitLab CE.

1. Создаем отдельную директорию `gitlab-local`
2. Пишем docker-compose файл:
  - Используем образ image: `gitlab/gitlab-ce:19.2.1-ce.0`. Не используем latest, обновление должно происходить постепенно через
  промежуточные версии, для успешной миграции базы данных. latest подтянет автоматически последнюю версию при рестарте, данные повредятся.

  - Указываем `hostname: localhost`. Нужно это по большей части для внешнего вида (интерфейс, почта, подсказки - везде будет указан localhost
  вместо id контейнера). Адрес по которому GitLab считает себя доступным снаружи указываем дальше в external_url, в конфиге.

  - `restart: unless-stopped` - автоматический перезапуск контейнера в случае падения контейнера, перезагрузки демона Docker / всей системы.

  - `environment:` - задаем переменные окружения.

  - Особая переменная окружения: `GITLAB_OMNIBUS_CONFIG`. Конфиг GitLab, пишем `GITLAB_OMNIBUS_CONFIG: |` -  `|` создаем блок, в котором код
  выполняется на Ruby, а не на YAML. Внутри контейнера настраивается Chef, система управления конфигурациями, написанная на Ruby. Из него
  уже генерируются реальные конфиги (nginx, postgres, puma и т.д.)

    - external_url 'адрес' - указываем адрес, по которому GitLab считает себя доступным снаружи
    - gitlab_rails['gitlab_shell_ssh_port'] = порт - проброс порта для ssh.
    - puma['worker_processes'] = значение - ограничение веб сервера
    - sidekiq['max_concurrency'] = значение - ограничение фоновых задач
    - prometheus_monitoring['enable'] = false - метрики
	
    Последние 3 параметра нужны только для оптимизации потребления ресурсов системы.


  - `ports:` - проброс портов

  - `volumes:` - указываем тома

  - healthcheck нужен чтобы избежать бесконечных перезагрузок а также чтобы при первом запуске контейнер мог адекватно запуститься

  - `volumes` обязательно указываем в конце


3. Выше указаны настройки, используемые мной. Настройки puma, sidekiq, prometheus не обязательны и настраиваются отдельно под возможности 
  каждой отдельной системы. Также в зависимости от системы настраивается отдельно healthcheck.

4. Запуск - http://localhost:порт. Логин - root, пароль создается автоматически `docker exec gitlab cat /etc/gitlab/initial_root_password`.
   В течение 24 часов необходимо сменить пароль.

5. Обнаружение и устранение проблем:
  `docker inspect -f {{.RestartCount}} gitlab` показывает количество автоматических рестартов контейнера
  `docker logs gitlab` покажет логи, `docker logs -f gitlab` покажет логи в реальном времени
  `docker exec gitlab gitlab-ctl tail` покажет логи внутренних процессов (nginx)
